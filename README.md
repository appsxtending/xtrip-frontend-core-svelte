# XTrip Svelte foundation

Private standalone @xtrip/ui-svelte foundation, version 0.2.0. F0.1 provides the adapter-node SSR host; F0.3 adds 37 reusable component families, independently versioned design-token/i18n packages and an interactive SSR workbench. F0.4 adds the opt-in session integration workbench; product applications follow in later approved tasks. F0.2 adds isolated API client/mock packages; its final canonical-example acceptance is explicitly deferred by the owner.

Use Node 24.18.0. Run `npm ci`, then `npm run dev` and open http://127.0.0.1:5173. Production: set XTRIP_WEB_ORIGIN to the canonical external origin before `npm run build`; set HOST and PORT at runtime, then `npm start`. The default build origin is http://127.0.0.1:4173 for local production tests. SvelteKit 3 uses build-time paths.origin instead of the removed runtime ORIGIN variable. Development derives the Vite request origin. Never trust forwarded origins without a trusted reverse proxy. The workbench is non-indexable and not an authenticated product application; do not place tenant data in it.

`npm run verify` first checks deterministic generation and canonical examples with the exact owner-approved development exceptions, then runs lint/format, strict typecheck, unit/component/architecture tests, production SSR and library build, and Chromium Playwright journeys. Install the browser with `npx playwright install chromium`. Evidence and visual fixtures are written to ignored test-results and playwright-report directories. Initial screenshots are checked for deterministic rendering and manually reviewed; no historical visual regression baseline is claimed. F0.1 local budgets: decoded route JavaScript under 200 kB and CSS under 80 kB. Rendering budgets additionally check local TTFB < 2 s, LCP < 2.5 s, CLS < 0.1 and observed interaction event duration < 200 ms. These are laboratory checks, not field INP/Core Web Vitals or release certification.

Approved F0.1 through F0.4 source/configuration paths are catalogued in contracts; generated build output is ignored. The library exports the 37 presentation components and locale helpers, with no server policy, route, workbench or API export. The SSR demo uses an allowlisted appearance form; it changes the URL and does not persist user data. Origin and Fetch-Metadata checks, SvelteKit CSRF, nonce CSP, Trusted Types and private response headers protect the host boundary.

The real backend is at http://localhost:4000. F0.1 does not make business API calls; F0.2 establishes the pinned generated client and real-API journeys. API health, readiness and public-contract alignment are recorded separately in the requirements checkpoint. Git origin is https://github.com/appsxtending/xtrip-frontend-core-svelte.git (supplied by the owner). Package publication remains disabled.

## F0.2 client and real API integration

`@xtrip/api-client` and `@xtrip/api-mocks` are private, independently versioned workspaces. UI exports import neither. `npm run build:packages` emits package-local `dist` artifacts. Consumer code imports package exports, not another repository's source. The generator's TypeScript 5.9.3 compiler is isolated from the SvelteKit host's TypeScript 6.0.3. MSW 2.15.0 satisfies Vitest's supported peer range.

Run `npm run generate:api` only after accepting a new contract baseline. `npm run check:api` verifies pinned hashes, complete operation ownership, deterministic regeneration and every canonical example under the exact development deferral described below. The snapshot contains 350 operations; generated request methods expose 330 frontend-consumed operations and exclude 20 internal/non-UI operations. Generated DTOs retain decimal strings, dates and principal-specific schemas without arithmetic or invented fields. Runtime transport guards reject unknown operations, origin overrides and path traversal; clients have immutable per-instance credentials, omit cookies, reject redirects and do not retry mutations.

For deterministic tests, select explicit canonical response scenarios with `createCanonicalHandlers`, and start MSW with `onUnhandledRequest: 'error'`. Invalid canonical examples fail during handler construction. Requests are schema-validated. Mocks are never active in the real-API Playwright project.

Run `npm run test:api:real` against the selected API. Default origin is `http://localhost:4000`; override with `XTRIP_API_ORIGIN`. The owner-provided ignored `.env.test` supplies `API_USERNAME`, `API_PASSWORD`, `API_TENANT`; use `XTRIP_TEST_ENV_FILE` for another local file. Credentials remain in process memory and are never committed, attached to evidence or included in browser traces. Missing credentials fail the authenticated test explicitly. Evidence identifies the profile only as `owner-provided-env-test`. No synthetic data is seeded or modified by this task; login creates the normal API authentication session and the authenticated operation is a geography read.

Acceptance on 2026-10-02: real contract equality, anonymous geography rejection, and successful credential login plus schema-valid authenticated geography read passed against API commit `542ed682c420d525631dbd53d42ef15d4421a9f8`. Foundation browser regression remains separate (`npm run test:e2e`). GitHub CI runs deterministic gates; the local API/profile is not reachable from hosted CI, so local real-API evidence is recorded separately and is not claimed as a hosted-CI result.

## Canonical contract blocker

F0.2 implementation is accepted for continued development with an **owner-approved deferral** (2026-10-08). Final canonical acceptance remains pending. The strict gate validates 2,436 frontend-consumed canonical examples and reports **91 JSON Schema diagnostics across 25 examples and 16 operations**. Diagnostic count includes failed `oneOf` branches; it is not a count of distinct defective examples. The original contracts and examples are preserved. Product contract hashes normalize UTF-8 text to LF so Git checkout line endings cannot create false drift. `npm run check:api` and `npm run verify` skip only the 25 exact example identities recorded in `contracts/api-baseline.json`, tied to the current contract hash. New failures still block; resolved entries require removal. `npm run check:api:strict` and `npm run verify:release` continue to reject all malformed examples. Revisit this deferral at F12.3, before final release acceptance, when the owner supplies the fixed API. Invalid examples remain unavailable to mock handlers.

- `GET /v1/public/checkouts/{checkoutId}` and `GET /v1/public/payments/return`: their `202` examples contain status 202, while the referenced problem schema requires status >= 400.
- Saved-search error examples: POST collection 409; GET item 404; PUT item 404/409; DELETE item 404; POST item execute 404. These omit required `detail`, `message_key` and `timestamp`.
- Platform-plan/subscription error examples: POST plans 409/422; GET plan 404; PUT plan 404/409; POST plan versions 404/409/422; GET plan versions 404; POST version publish 404/409; POST plan retire 404/409; GET tenant subscription 404; PUT tenant subscription 404/409/422. These omit the same problem fields, with additional branch diagnostics from their `oneOf` schemas.

Exact operation/status/schema-keyword diagnostics are reproducible with `node tools/check-api-contract.mjs`. Upstream repair must happen in the backend authority under its own approved task; this frontend task does not change backend schemas or synthesize missing fields. After an approved repin, regenerate, run the full aggregate and real API acceptance, then close F0.2. Pricing UI stage/line reconciliation and complete business journeys remain future consuming-task acceptance; this task establishes schema/decimal/projection preservation only.

## F0.3 design system and workbench

Open `/` and select any of the 37 component families. URL controls preserve locale (English, Arabic RTL, Thai or expanded pseudolocale), light/dark theme, audited forest/indigo brand presets, density and ten remote-data states. Drawer selection survives reload and browser history. All stories render on the server; their clearly labelled illustrative records and callbacks are local demonstrations, not live business data.

Consumers import components from `@xtrip/ui-svelte`, locale helpers from `@xtrip/i18n`, and `@xtrip/design-tokens/tokens.css` through their Tailwind 4 styling entry. The token package uses Open Props and semantic utilities, logical spacing, forced-color and reduced-motion adaptations. It follows the approved green operational design with an accessible system font fallback. Melt dialog builders are wrapped privately and use the direct action API so consumers need no Melt preprocessor.

The package includes navigation, form controls, searchable supplied-data pickers, responsive records, sortable/filterable/selectable/paginated grids, exact decimal displays, explicit drift acceptance, notifications, themes, chart/map alternatives and import review. Price components display only the authorized projection supplied by the caller; they do not determine authorization, calculate totals, reorder pricing stages or reconstruct hidden fields. Import application requires a caller-confirmed validation result and explicit user acceptance. Chart/map provider content is supplied through snippets, with accessible data/list alternatives.

This is the shared presentation foundation. Virtualized business rate grids, real geography search, provider integrations, server-enforced permissions, authentication and complete pricing/API journeys belong to their consuming roadmap tasks. The workbench must never receive production tenant data. No deployment or registry publication is performed.

Central component tests exercise state changes and exact decimal preservation; the SSR suite renders every family, and the browser suite audits every family plus dialog focus, RTL keyboard navigation, URL history and no-JavaScript behavior. The npm package file allowlist excludes server code, routes, API packages and demonstration stories. The existing real-API project remains separate from all illustrative UI stories.

## F0.4 session integration

The separate `@xtrip/web-runtime/server` package owns session cookies, RS256 verification, exact permission guards, CSRF, refresh serialization and generated-client calls. Its `/errors`, `/types` and `/reconciliation` exports are safe for browser use. UI component exports still contain no API/session runtime. `/session/login`, `/session` and `/session/poll` are opt-in core integration surfaces, not completed tenant/agent/admin applications.

To enable the local integration workbench, configure `XTRIP_SESSION_ENABLED=true`, `XTRIP_SESSION_STORE=single-process-workbench`, `XTRIP_WEB_ORIGIN`, `XTRIP_API_ORIGIN`, a random 32-byte base64 `XTRIP_SESSION_KEY`, and trusted `XTRIP_JWT_PUBLIC_KEY_BASE64`, `XTRIP_JWT_ISSUER`, `XTRIP_JWT_AUDIENCE`. Explicit `XTRIP_ALLOW_LOOPBACK_SESSION=true` permits HTTP only on loopback for local development. Do not put private signing keys in the frontend. The API's development fallback creates an ephemeral signing key in memory; it does not provide a public-key discovery endpoint. Supply persistent trusted public verification configuration before real SSR session acceptance.

The cookie carries only an authenticated encrypted opaque reference. Tokens live in the bounded server store, with an eight-hour absolute session cap and five-minute MFA-pending cap. A process restart invalidates local sessions. The supplied store and CSRF registry are for the single-process workbench. A deployed multi-instance application must supply shared storage/locking and shared CSRF state; this task does not claim distributed deployment readiness. Refresh has no automatic retry after an ambiguous response, and logout prevents a concurrent refresh from restoring the local session. API authorization remains authoritative; local claim checks do not replace backend revocation or permission-version checks.

Platform authentication cannot use this tenant/agent demonstration: the pinned platform login omits tenantId while refresh/logout/TOTP schemas require one. No tenant identifier is fabricated; platform lifecycle integration remains a contract dependency for its consuming task. SSO and MFA enrollment/recovery are not implemented here.

Every same-origin state-changing action, including the appearance preview, now consumes a one-use identity-bound CSRF challenge and checks Origin/Fetch-Metadata. Each rendered form contains its challenge. A consumed challenge requires a new page load. The session read proxy exposes only a fixed generated geography operation and safe presentation projection, never arbitrary API paths.

Reconciliation uses a component-owned TanStack query cache seeded with SSR data. Keys include the verified principal/tenant/permissions fingerprint. Polling runs at ten-second intervals for at most five attempts or sixty seconds, pauses while hidden/offline, cancels on unmount, honors bounded retry-after, and stops on terminal/auth errors. It is a provisional read-polling adapter, not a push transport. No mutation is retried optimistically.

`npm run test:e2e` starts an isolated canonical-schema-validated API fixture with synthetic signing keys. `npm run test:session:real` instead starts the built SSR host with ignored `.env.session-test` and uses the existing ignored `.env.test` profile. That project disables screenshots, traces and video; no credentials belong in retained evidence. The existing `npm run test:api:real` remains a separate direct generated-client regression. Final F0.4 evidence and any unresolved configuration are recorded in the authority checkpoint.

F0.4 acceptance completed on 2026-10-09 after the owner configured matching API signing keys and restarted the API. The mock-free SSR login, protected read, refresh, polling and logout journey passed (one test, 6.9 seconds); the separate direct API project passed all three checks (6.8 seconds). Frontend configuration contains only the trusted public verification key and an independent session cookie key in ignored `.env.session-test`. No backend files were modified. Deterministic acceptance comprises 53 tests and 55 browser checks with green hosted CI on implementation commit `563299326206a49cc830902fc31cd29ad8ad5d94`. Existing F0.2 final-release deferrals and the single-process workbench limitation remain unchanged.
